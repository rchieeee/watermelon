# Watermelon Irrigation (Flutter)

Irrigation monitoring and decision support for a watermelon field.
Four tabs: Home, Irrigation, Analytics, Field.

## Setup

1. Create a Flutter project, then replace its `lib/`, `pubspec.yaml`
   and `assets/` with the ones from this folder:
   ```
   flutter create watermelon_irrigation
   ```
2. Put your dataset at `assets/data/watermelon_irrigation.csv`.
   Required header (any column order):
   ```
   timestamp,soil_moisture_pct,temperature_c,humidity_pct,rain_probability_12h_pct,rainfall_forecast_12h_mm,growth_stage,irrigation_needed,watering_duration_min,next_irrigation_hours
   ```
   Timestamps like `2026-09-27 08:30:00` or `9/27/2026 8:30` both work.
   Empty cells, `NA`, `NaN` and `null` are treated as missing.
3. Run:
   ```
   flutter pub get
   flutter run
   ```

Requires Flutter 3.22 or newer. The Atkinson Hyperlegible font is
downloaded by `google_fonts` on first launch, so the device needs internet
once. On Android release builds, make sure
`<uses-permission android:name="android.permission.INTERNET"/>` is in
`android/app/src/main/AndroidManifest.xml`.

## How it behaves

- **Data labels.** Readings are tagged Current, Historical, Forecast or
  Predicted. If the newest reading is older than 3 hours
  (`FieldController.staleAfter`), readings are tagged Historical and a
  notice explains it.
- **Missing data.** A missing value shows "... unavailable". A missing
  `irrigation_needed` shows "Irrigation recommendation unavailable". No
  value or recommendation is ever generated by the app.
- **Analytics ranges.** Only ranges the data can fill are offered
  (7 days needs more than 1 day of data, 30 days needs more than 7).
  Ranges are counted back from the newest reading; "Today" becomes
  "Latest day" when the newest reading is not from today.

## Connecting real systems later

- **Live data (ESP32 via Firebase):** implement `FieldDataRepository`
  in `lib/data/field_data_repository.dart` and pass it in `main.dart`.
- **Trained ML model:** `ApiPredictionService` in
  `lib/services/irrigation_prediction_service.dart` already posts the six
  inputs and reads the three outputs. The expected JSON is documented there.
